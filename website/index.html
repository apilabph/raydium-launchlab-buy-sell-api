01 / The workflow

One clear path to your trade.

The API prepares a transaction. Your bot stays in control of whether to execute it.

01 — INSPECT

Start with the right market.

Provide the token and your public wallet. The quote identifies the current supported venue and its output units.

02 — PREPARE

See what you will receive.

Build with a slippage limit and maximum service fee. Review simulation, minimum output and any setup costs.

03 — SIGN LOCALLY

Let your bot make the call.

Verify the transaction against your own trading rules. Sign locally, send through your RPC and check the confirmed result.

03 / Quick start

            
From first call to your own bot.

          

          

            No signup step. Start with a read, learn the response, then
            integrate local signing.
          

        

        

          

            Before you startAmount unitsRead a responseSign & confirmAPI reference
          

          

            

              
1. Make a read-only request

              

                The hosted public beta needs no API key. Choose
                an operation in the playground, paste a supported token’s public
                address and use the generated code. JavaScript examples run in
                Node 22 or 24; Python examples use the standard library.
              

              

                A quote needs a public wallet address but is not simulated. A
                transaction build needs a wallet funded for the input, network
                fees and account rent.
              

              

                Public beta limits: 6 requests per minute per IP and 20 per
                minute per service at the edge. These limits are approximate per
                edge location; provider and hosting limits also apply.
              

            

            

              
2. Get the units right

              

                Buying: "amount": "0.01" means
                0.01 SOL. Selling:
                "amount": "1000000" means one million raw token
                units. For a token with 6 decimals, that equals 1 displayed
                token. Use strings to avoid floating-point rounding.
              

              

                Set slippageBps: 100 for a 1% tolerance and
                maxServiceFeeBps: 25 for a 0.25% fee cap. Slippage
                is a price tolerance, not an additional fixed fee.
              

            

            

              
3. Check the result before signing

              
    
                
  • 
                  venue, poolAddress and contextSlot: the checked market and
                  point-in-time chain state.
                
    • 
                
  • 
                  expectedOut, minOut and outputUnit: output values are raw
                  token units for buys and lamports for sells.
                
    • 
                
  • 
                  simulation.status is not_run for quotes. Use /api/trade for a
                  simulated unsigned build.
                
    • 
                
  • 
                  Review feeAccountSetupRequired and rent information in a
                  build. Existing wrapped-SOL accounts are preserved.
                
    • 
              

            

            

              
4. Sign and confirm inside your bot

              

                Use POST /api/trade with the same request body.
                Inspect the returned transaction, wallet, token, amount, fee
                recipient and minimum output. Check an independent price limit
                before signing. Keep keys in your local signer; this website
                never needs them.
              

              

                Deserialize the base64 transaction with your Solana wallet
                tooling, inspect its instructions and sign it locally. Submit
                through your RPC and verify the transaction result. Rebuild
                after blockhash expiry; do not blindly resend after an uncertain
                submission.
              

              

                Wait for confirmation and check success before treating a buy or
                sell as complete. A successful build or simulation cannot
                guarantee later execution.
              

            

            

              
Endpoint reference

              

                POST /api/quoteRequest an estimate. This endpoint does not simulate or build
                  a transaction.
              

              

                POST /api/tradeBuild an unsigned transaction after simulation. Your bot
                  signs and submits it separately.
              

              

                GET /api/capabilitiesPublished capability and setup information. This does not
                  execute a test trade.

05 / Pricing

            
Pay when a swap succeeds.

            
0.25%

            

              Service fee per successful trade.
No hosted beta API-key
              charge or monthly subscription.
            

            

              A failed swap reverts the service fee. Network gas can still be
              charged.
            

          

          

            

              Buy
              

                0.25% of the requested SOL input, included in that input. The
                remainder funds the swap.
              

            

            

              Sell
              

                0.25% of actual SOL proceeds, deducted before your payout.
                Existing wrapped-SOL accounts are preserved; proceeds remain
                WSOL when one already exists.
              

            

            

              Other costs
              

                Network and protocol fees are separate. Account rent may also
                apply. If the service’s fee account is missing, the first trader
                pays its creation cost, disclosed by the build.

06 / Help when you need it

          
Less time guessing.
More time building.

          

            Start here when a request doesn’t do what you expected.
          

          Open a GitHub issue ↗
        

        

          

            Where do I get an API key?
            

              You do not need one for this hosted public beta. Self-hosting
              credentials described in the repository are operator settings.
              They are not keys issued to hosted users.
            

          

          

            Did my API request buy or sell a token?
            

              No. Inspection and quotes only read or simulate. A build returns
              an unsigned transaction. A trade happens after your own bot signs,
              submits and confirms it.
            

          

          

            What does SETUP_REQUIRED mean?
            

              The operator has not completed settlement deployment. It is not a
              request to give us your private key, increase slippage or deposit
              into a contract. Check release status before integrating
              execution.
            

          

          

            Why might a token fail after graduation?
            

              A token may be migrating, its destination may be unsupported, or
              its state may have changed after quoting. Request a fresh quote
              and check coverage. Stage detection reduces stale-route mistakes;
              it cannot guarantee success.
            

          

          

            What should I do after a timeout or failed trade?
            

              If you only requested a quote or build, nothing was broadcast by
              this API. If your bot already submitted a signed trade, inspect
              its transaction ID and chain status before retrying. A second
              signed transaction can create a second trade.
            

          

          

            How fast is it?
            

              The playground measures the duration of your own request. API
              build time and blockchain confirmation are different. We have not
              established a production latency SLA or comparative speed
              advantage.
            

          

          

            How do I report a problem?
            

              Include the API name, operation, error code, request ID,
              approximate time and a redacted request. Never share private keys,
              recovery phrases, provider credentials or signed transactions.
              Support is through GitHub issues; no response-time SLA is offered.
            

          

          

            Is this an official Raydium LaunchLab service?
            

              No. APILabPH builds independent integrations. The launchpad and
              network names identify compatibility; they do not imply
              endorsement.
